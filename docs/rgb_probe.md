# Полуавтоматический электрический probe для FW 0.1.1

`tools/rgb_probe.py` запускается отдельной командой оператора. Подключение
устройства и обычная serial_console не запускают сканирование. FW не меняется.

## Симуляция — без устройства и без pyserial

```powershell
python tools/rgb_probe.py --simulate --source 14 --pins 32,33,34 --output build/probe_demo/led49
python tools/rgb_probe.py --simulate --source 14 --pins 1-40 --output build/probe_demo/source14
python tools/rgb_probe.py --simulate --sink 32 --pins 13-15 --output build/probe_demo/sink32
python -m unittest discover -s tests -p 'test_*.py' -v
```

Каждый output — новый префикс: существующие результаты не перезаписываются.
Симулятор использует виртуальное время. Для известных направлений выдаёт
средние токи 1033/886/794 мкА, для остальных — условные 16 мкА. MAX и число
отсчётов моделируются. Это тестовые данные, не аппаратные измерения;
`simulation=true` сохранено в JSON и каждой строке CSV. Изменение длительности
в симуляторе не является физической моделью LED. Оптического вывода нет.

## Операторский запуск

Не открывать один порт одновременно в probe и serial_console. Проверить
соединения и ориентацию FPC, оставить U13 OPEN и R1=2700 Ом. Подставить
фактический порт. `--confirm-scan` явно подтверждает подготовку и разрешает
напечатанный план; `--arm-seconds` явно разрешает один ARM после проверок.

Сначала ограниченная серия на известных направлениях:

```powershell
python -m pip install -r tools/requirements.txt
python tools/rgb_probe.py --port COM19 --source 14 --pins 32,33,34 --confirm-scan --arm-seconds 60 --output results/rgb_led49_run01
```

Подготовленный план SOURCE=14, SINK=1…40 — 39 пар без KP14:

```powershell
python tools/rgb_probe.py --port COM19 --source 14 --pins 1-40 --duration-ms 150 --pause-ms 500 --threshold-ua 100 --current-limit-ua 1800 --confirm-scan --arm-seconds 60 --output results/rgb_source14_run01
```

Фиксированный SINK задаётся через `--sink N`; `--pins` тогда перечисляет
SOURCE. Например, `--sink 32 --pins 13-15` — пары 13→32, 14→32, 15→32.
Одинаковые контакты исключаются, повторы удаляются, номера только 1…40.
Реальное аппаратное сканирование инструментом при разработке не выполнялось.

## Параметры и остановка

* Длительность 150 мс по умолчанию, допустимо 10…300 мс — пределы FW.
* Пауза 500 мс по умолчанию, `--pause-ms` — 0…60000 мс.
* ARM 1…60 с, в hardware-режиме параметр обязателен. Перед PAIR резервируется
  длительность, timeout ответа и небольшой запас. FW — окончательный арбитр.
* Предел остановки `--current-limit-ua` по умолчанию 1800, максимум 2000 мкА.
  Это проверка CURRENT и MAX/AVG из DONE, не регулятор тока. Между опросами
  возможны незамеченные пики; аппаратный R1 и защита FW остаются обязательными.
* Диагностический `--threshold-ua` по умолчанию 100, допустимо от 0 до значения
  строго ниже limit. Кандидаты — завершённые пары с AVG строго выше порога.
* `--response-timeout` по умолчанию 1 с, допустимо 0,1…2 с.

Последовательность: OFF → INFO (проверка 0.1.1) → STATUS DISARMED с EN=0
и FAULT=NONE → ADCSTATUS → CURRENT → SELFTEST → единственный ARM.
Перед каждым PAIR повторяются STATUS IDLE, ADCSTATUS/CURRENT, SELFTEST и
проверка оставшегося разрешения. ACK сверяется с параметрами, DONE — с ID.
Во время импульса CURRENT/ADCSTATUS опрашиваются примерно каждые 20 мс
плюс время обмена. После DONE и в паузах также проверяются состояние и ADC.

Остановка при FAULT/ERR, неверном/устаревшем ADC, ненулевых ERRORS/OVR_COUNT,
превышении host-предела, неверном ACK/DONE, отсутствии ответа/DONE, USB-ошибке,
истечении ARM и Ctrl+C. Исторические ошибки ADC тоже запрещают начало серии.
Инструмент не очищает FAULT, не сбрасывает счётчики и не повторяет PAIR/ARM.
ADC_STALE_MS остаётся 5 мс. Для следующей серии нужен новый явный запуск.

В конце и при ошибках предпринимается отправка OFF с ограниченным ожиданием
подтверждения, затем закрытие порта. При обрыве USB доставка OFF может быть
невозможна; ошибка сохраняется, timeout FW остаётся независимой защитой.
Это не измерение физических фронтов EN. Код выхода: 0 — успех, 130 — Ctrl+C,
1 — другая ошибка.

## CSV и JSON

Для префикса создаются `.json`, `.csv` и `_candidates.csv`. JSON содержит
план, параметры, статус серии, все записи, события TX/RX и отдельный массив
`current_candidates`; candidates CSV содержит только завершённые пары выше
порога. Каждый record: SOURCE/SINK, ID, длительность, AVG/MAX, SAMPLES,
REASON, FAULT, UTC-времена создания/ACK/DONE, статус, признак кандидата,
признак симуляции и ошибка. Недоступные значения — null/пустые, не нулевые
фиктивные токи. Пара, остановленная до ACK, может иметь ID=null.

Данные сохраняются после каждого завершённого PAIR, при остановке — также
незавершённая запись. JSON заменяется атомарно, CSV представляет снимок
строк. При ошибке диска OFF всё равно отправляется, но сохранность последней
записи не гарантируется. `COMPLETED` означает TIMEOUT и успешные проверки,
не обнаружение свечения; визуальные наблюдения LED нужно фиксировать отдельно.
Сохраняются `STOPPED_FAULT`, `ERROR_ADC`, `OVER_LIMIT`, `MISSING_DONE`,
`ARM_EXPIRED`, `INTERRUPTED`, другие причины и `cleanup_error`.

Демонстрации писать в игнорируемый `build/`. `results/` не исключён из Git:
реальные журналы добавлять адресно после проверки, не всем каталогом.
Камера, OpenCV и GUI отсутствуют. События и времена ACK/DONE предусмотрены
для будущего отдельного механизма синхронизации и записи наблюдаемых LED.

## Выполненные программные проверки

Пройдены 12 тестов самого probe и четыре теста схемы (16 unittest), а также
существующие CTest `firmware_logic` и `adc_acquisition`. Проверены известные
три пары, 39 пар SOURCE=14, режим фиксированного SINK, CSV/JSON/кандидаты,
ошибки и Ctrl+C, истечение ARM без продления, отсутствие подтверждения OFF,
отказ от запуска без подтверждения оператора, фрагментация/coalescing USB,
короткая запись USB и неверная кодировка. Отдельно успешно выполнены три
CLI-демонстрации из раздела симуляции. Прошивка не менялась и повторно
не прошивалась; это не аппаратная проверка нового инструмента.
