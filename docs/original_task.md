# Задача: разработка первоначальной прошивки для стенда исследования RGB-подсветки MSI GS75

Ты выступаешь в роли опытного Embedded C / STM32-разработчика.

Необходимо создать новый проект прошивки для тестовой платы, предназначенной для исследования неизвестной распиновки RGB-подсветки клавиатуры MSI GS75.

Проект разрабатывается с нуля, но должен учитывать опыт существующего проекта USB-клавиатуры:

https://github.com/AlexeyNV/GS75_Keyboard

**Важно:** новый проект является самостоятельным и не должен изменять файлы репозитория `GS75_Keyboard`.

Название нового проекта и GitHub-репозитория:

`GS75_RGB_Research`

## 1. Цель проекта

Разработать первоначальную рабочую прошивку STM32F411RET6, позволяющую:

1. Подключаться к компьютеру по USB CDC.
2. Принимать текстовые команды из последовательного порта.
3. Независимо управлять двумя группами аналоговых мультиплексоров 74HCT4051.
4. Выбирать любые два контакта 40-контактного разъёма RGB-подсветки.
5. Подключать один контакт к ограниченному по току источнику напряжения, другой — к цепи возврата тока.
6. Измерять ток через встроенный АЦП STM32.
7. Автоматически отключать обе группы коммутаторов после завершения эксперимента.
8. Предоставлять диагностику работы платы и безопасный режим проверки без подключённой RGB-платы.
9. В дальнейшем взаимодействовать с управляющим Python-скриптом для автоматизированного оптического сканирования подсветки.

Сейчас разрабатываем только первую версию прошивки и минимальный инструмент для взаимодействия с ней.

Компьютерное зрение, веб-камеру, GUI и автоматический перебор 1560 комбинаций пока НЕ реализовывать.

## 2. Исходные данные

Микроконтроллер: STM32F411RET6, LQFP64.

Рабочее напряжение микроконтроллера: 3,3 В.

Логика коммутаторов и дешифраторов питается от USB 5 В.

Источник тактирования: внешний кварц 8 МГц.

Предпочтительная рабочая частота STM32: 96 МГц, USB FS — 48 МГц.

Инструменты:
- STM32CubeMX.
- STM32 HAL / CubeF4.
- STM32CubeIDE-совместимая структура проекта.
- VSCode как основная среда редактирования.
- Git/GitHub.
- Python 3 для тестового USB CDC-клиента.

Входной документ: схема EasyEDA `PCB_light_keyboard`, файл `SCH_PCB_light_keyboard_2026-11-09.json`.

Используй исходную схему как главный источник информации о физических соединениях.

Если файла нет в рабочем каталоге, сначала найди его среди доступных вложений или запроси размещение в `hardware/easyeda/`. Не подменяй отсутствие схемы предположениями.

Перед реализацией проверь правильность всей приведённой ниже распиновки по схеме.

## 3. Аппаратная архитектура

Плата содержит:

- U1–U10: 74HCT4051PW,118.
- U11–U12: 74HCT138PW,112.
- FPC1: 40-контактный разъём RGB-платы.
- U21: STM32F411RET6.
- R1 = 2,7 кОм: ограничение тока основной положительной цепи.
- R18 = 1,5 кОм: дополнительная ветвь ограничения тока через перемычку U13.
- R2 = 100 Ом: измерительный резистор между SINK_BUS и GND.
- R3 = 1 кОм: последовательный резистор между SINK_BUS и ADC_SENSE.

В начальных испытаниях перемычка U13 разомкнута. Используется только ветвь R1 = 2,7 кОм.

U1–U5 используются для выбора контакта SOURCE.

U6–U10 используются для выбора контакта SINK.

U11 выбирает активную микросхему группы SOURCE.

U12 выбирает активную микросхему группы SINK.

Нумерация контактов в программном интерфейсе: KP1–KP40.

### 3.1. Распиновка STM32

| Сигнал | GPIO STM32 | Назначение |
|---|---|---|
| SRC_CH0 | PA4 | Адрес S0 группы SOURCE |
| SRC_CH1 | PA5 | Адрес S1 группы SOURCE |
| SRC_CH2 | PA6 | Адрес S2 группы SOURCE |
| SRC_BANK0 | PA7 | Адрес A0 дешифратора U11 |
| SRC_BANK1 | PA8 | Адрес A1 дешифратора U11 |
| SRC_BANK2 | PA9 | Адрес A2 дешифратора U11 |
| SRC_BANK_EN | PA10 | Разрешение U11 |
| SNK_CH0 | PC6 | Адрес S0 группы SINK |
| SNK_CH1 | PC7 | Адрес S1 группы SINK |
| SNK_CH2 | PC8 | Адрес S2 группы SINK |
| SNK_BANK0 | PC9 | Адрес A0 дешифратора U12 |
| SNK_BANK1 | PC10 | Адрес A1 дешифратора U12 |
| SNK_BANK2 | PC11 | Адрес A2 дешифратора U12 |
| SNK_BANK_EN | PC12 | Разрешение U12 |
| ADC_SENSE | PA0 | Измерение тока |
| USB_DM | PA11 | USB FS D- |
| USB_DP | PA12 | USB FS D+ |
| SWDIO | PA13 | Отладка |
| SWCLK | PA14 | Отладка |

Дополнительные сигналы, имеющиеся в схеме:

- PB6 — UART_TX.
- PB7 — UART_RX.
- PB3 — SWO.
- PB2 — boot1.

На первом этапе UART не требуется, USB CDC является основным интерфейсом.

**Критически важно:** PA9 занят сигналом SRC_BANK2. Поэтому необходимо отключить использование PA9 как USB VBUS sensing. Настроить USB Device с отключённым аппаратным VBUS sensing и проверить отсутствие конфликта в CubeMX.

Сохранить возможность SWD-отладки.

### 3.2. Работа дешифраторов и мультиплексоров

74HCT138:
- Выходы Y0–Y7 активны низким уровнем.
- E1 и E2 активны низким уровнем и в схеме подключены к GND.
- E3 активен высоким уровнем и управляется сигналом BANK_EN.

74HCT4051:
- Вход E активен низким уровнем.
- При E=HIGH все аналоговые каналы отключены.
- S0/S1/S2 определяют выбранный канал Y0–Y7.

Поэтому:

`SRC_BANK_EN = 0` — вся группа SOURCE отключена.

`SNK_BANK_EN = 0` — вся группа SINK отключена.

`SRC_BANK_EN = 1` — разрешена выбранная микросхема SOURCE.

`SNK_BANK_EN = 1` — разрешена выбранная микросхема SINK.

Дешифраторы U11 и U12 используют выходы Y4–Y0 для выбора пяти мультиплексоров.

Предварительная карта:

| Контакты FPC | SOURCE | SINK | Адрес BANK |
|---|---|---|---|
| 1–8 | U1 | U6 | 4 |
| 9–16 | U2 | U7 | 3 |
| 17–24 | U3 | U8 | 2 |
| 25–32 | U4 | U9 | 1 |
| 33–40 | U5 | U10 | 0 |

Алгоритм расчёта:

```c
channel = (pin - 1) % 8;
bank = 4 - ((pin - 1) / 8);
```

Проверить его по реальной схеме перед использованием.

Не путать логическую нумерацию KP1–KP40 с физическим направлением нумерации контактов FPC. Ориентация реального шлейфа должна быть проверена отдельно.

## 4. Безопасность — обязательные требования

Считай, что RGB-плата может быть неизвестной электрической схемой с возможными внутренними соединениями, общими электродами и чувствительными светодиодами.

### 4.1. Безопасное состояние

При следующих событиях обе группы мультиплексоров должны отключаться:

- Включение питания.
- Reset.
- Начало инициализации.
- Ошибка прошивки.
- Завершение временного импульса.
- Команда OFF.
- Аварийная ошибка измерения тока.
- USB Suspend, если событие поддерживается используемым USB-стеком.
- Истечение времени разрешения экспериментов.

Никакие контакты FPC не должны включаться автоматически при подаче питания или подключении USB.

Продумать порядок инициализации GPIO с учётом аппаратных подтягивающих резисторов на BANK_EN.

### 4.2. Алгоритм переключения

При выборе новой пары:

1. Отключить SRC_BANK_EN и SNK_BANK_EN.
2. Установить адреса SOURCE.
3. Установить адреса SINK.
4. Дождаться безопасного времени переключения согласно datasheet с запасом.
5. Разрешить выбранные банки.
6. Выполнить измерения.
7. По тайм-ауту снова отключить обе группы.

Не допускать переключения адресных линий при включённых банках.

### 4.3. Ограничения

Запретить:
- SOURCE = SINK.
- Номера контактов вне диапазона 1–40.
- Нулевую длительность.
- Бесконечное включение контактов.
- Параллельное выполнение двух команд PAIR.
- Подачу напряжения после ошибки до явного сброса ошибки оператором.

Для начальной версии использовать ограничение длительности одного импульса, например 10–300 мс.

Точное значение сделать конфигурируемым через compile-time settings, но не разрешать произвольное увеличение через USB.

Реализовать независимый от связи USB тайм-аут: обрыв связи с ПК не должен оставлять выбранную пару постоянно включённой.

Включение выходов разрешать только после явной команды ARM. После включения питания состояние DISARMED.

Для ARM установить тайм-аут, например 60 секунд, после которого устройство снова переходит в DISARMED и отключает выходы.

### 4.4. Измерение тока

R2 = 100 Ом подключён между SINK_BUS и GND.

PA0 измеряет напряжение через R3 = 1 кОм.

Для первоначальной оценки:

`I = V_ADC / 100 Ом`

Реализовать:
- Чтение raw ADC.
- Усреднение нескольких отсчётов.
- Расчёт напряжения в мВ.
- Расчёт тока в мкА.
- Проверку допустимости данных.
- Регистрацию среднего и максимального тока за время импульса.

Принять 12-битный ADC, номинальный VREF = 3,3 В, но выделить VREF и R_SHUNT в конфигурацию для последующей калибровки.

Не заявлять высокую точность измерений без калибровки.

При некорректном ADC или установленном аварийном пределе отключать выходы и возвращать ошибку.

Учитывать, что R1 физически ограничивает максимальный ток, поэтому программный предел должен быть согласован с реальной схемой и режимом перемычки U13.

Никакой автоматической переконфигурации на повышенный ток не делать.

## 5. Архитектура прошивки

Использовать разделение STM32CubeMX-generated code и прикладного кода.

Предлагаемая структура:

```text
firmware/
├── Core/
│   ├── Inc/
│   └── Src/
├── USB_DEVICE/
├── Middlewares/
├── Drivers/
├── App/
│   ├── Inc/
│   │   ├── app.h
│   │   ├── mux4051.h
│   │   ├── current_sense.h
│   │   ├── safety.h
│   │   ├── cli.h
│   │   └── board_config.h
│   └── Src/
│       ├── app.c
│       ├── mux4051.c
│       ├── current_sense.c
│       ├── safety.c
│       └── cli.c
└── README.md
```

Допускается изменить структуру, если это обоснованно.

Требования к архитектуре:

- Не помещать всю логику в main.c.
- Логику адресации SOURCE/SINK выделить в самостоятельный модуль.
- Не допускать дублирования GPIO-операций.
- Реализовать единый интерфейс `Mux_AllOff()`.
- Реализовать явную машину состояний: DISARMED, IDLE, ACTIVE, FAULT.
- Не использовать длительные блокирующие задержки в основном цикле.
- Не блокировать USB CDC во время импульса.
- Не использовать динамическое выделение памяти без необходимости.
- Использовать фиксированные буферы и проверку входных строк.
- Защитить обработку команд от переполнения буфера и некорректных параметров.
- Сделать конфигурацию ограничений централизованной.

Предусмотреть возможность в будущем подключить Python-программу, которая будет управлять стендом, получать измерения и синхронизировать их с камерой.

## 6. USB CDC и CLI

Реализовать человекочитаемый текстовый протокол.

Команды должны завершаться `\n`. Поддержать `\r\n`.

Ответы должны иметь однозначно определяемый формат.

Нужны команды:

### PING

```text
> PING
PONG
```

### INFO

Пример ожидаемой структуры:

```text
> INFO
FW: 0.1.0
MCU: STM32F411RET6
BOARD: GS75_RGB_Research
INTERFACE: USB_CDC
FPC_PINS: 40
MUX_SOURCE: 5x74HCT4051
MUX_SINK: 5x74HCT4051
ADC: PA0
SHUNT_OHM: 100
CURRENT_LIMIT_RESISTOR_OHM: 2700
STATE: DISARMED
```

Значения, зависящие от фактической конфигурации, должны выводиться из неё, а не из выдуманных результатов.

### HELP

Список поддерживаемых команд с кратким синтаксисом.

### STATUS

Текущее состояние:
- DISARMED / IDLE / ACTIVE / FAULT.
- SOURCE.
- SINK.
- Состояния разрешения банков.
- Остаток времени активного импульса.
- Код последней ошибки.

### OFF

Немедленно выключить обе группы мультиплексоров.

### ARM

Разрешить экспериментальные импульсы на ограниченное время.

```text
> ARM 60
OK ARM_TIMEOUT_S=60
```

Ограничить максимальный допустимый ARM timeout.

### DISARM

Отключить выходы и запретить новые импульсы до повторной ARM.

### PAIR

```text
> PAIR 12 34 300
```

Значение:
- SOURCE = 12.
- SINK = 34.
- Длительность = 300 мс.

При запуске:

```text
ACK ID=1 SRC=12 SNK=34 DURATION_MS=300
```

При завершении:

```text
DONE ID=1 STATE=OFF CURRENT_AVG_UA=... CURRENT_MAX_UA=... FAULT=NONE
```

Показания должны быть реальными, полученными с ADC. Если измерение недоступно, нужно вернуть соответствующий статус, а не фиктивные значения.

Команда выполняется асинхронно относительно обработчика USB CDC.

### CURRENT

Возвращать последнюю корректную выборку тока, её возраст и состояние измерения. При необходимости добавить raw ADC.

### DUMP

Выводить основные диагностические данные:
- Состояния GPIO.
- Выбранные адреса банков.
- Выбранные каналы.
- Состояние разрешения.
- Raw ADC.
- Состояние ошибок.

### SELFTEST

Пассивная самодиагностика:
- Проверка состояния прошивки.
- Проверка того, что банки отключены.
- Проверка ADC.
- Проверка конфигурации GPIO на уровне доступных программных средств.

Не утверждать, что SELFTEST проверяет физическую исправность мультиплексоров, если аппаратная обратная связь отсутствует.

### CLEARFAULT

Сброс аварийной блокировки после отключения выходов и проверки допустимости состояния.

Ошибки должны иметь машиночитаемые коды, например:

```text
ERR INVALID_PIN
ERR SAME_PIN
ERR INVALID_DURATION
ERR NOT_ARMED
ERR BUSY
ERR ADC_INVALID
ERR FAULT_LATCHED
```

## 7. Проверка адресации

Реализовать и проверить адресное преобразование для всех 40 контактов.

Проверить граничные значения:

- 1 → BANK=4, CH=0.
- 8 → BANK=4, CH=7.
- 9 → BANK=3, CH=0.
- 16 → BANK=3, CH=7.
- 17 → BANK=2, CH=0.
- 24 → BANK=2, CH=7.
- 25 → BANK=1, CH=0.
- 32 → BANK=1, CH=7.
- 33 → BANK=0, CH=0.
- 40 → BANK=0, CH=7.

Проверить корректность всех 1560 направленных пар SOURCE/SINK с различными контактами.

Вынести адресное преобразование в чистые функции C без зависимости от HAL и выполнить host-side unit tests.

## 8. Минимальный Python-клиент

Создать простой Python-скрипт для подключения к USB CDC через pyserial.

Пример:

```text
python tools/serial_console.py --port COM7
```

Скрипт должен:
- Открывать последовательный порт.
- Отправлять текстовые команды.
- Выводить ответы в консоль.
- Различать ACK, DONE и ERR.
- Корректно закрывать порт.
- Поддерживать Windows.

Пока не реализовывать графический интерфейс и автоматическое массовое сканирование.

## 9. Сценарий первого испытания

Первая проверка выполняется **без подключения оригинальной платы RGB-подсветки MSI**.

Нужно подготовить подробный документ `docs/bringup.md`.

Последовательность:

1. Подключить тестовую плату к USB.
2. Проверить питание 5 В и 3,3 В.
3. Проверить, что мультиплексоры отключены после Reset.
4. Убедиться, что USB CDC определяется компьютером.
5. Выполнить PING и INFO.
6. Выполнить SELFTEST.
7. Проверить выходные сигналы управления по доступным контрольным точкам.
8. Проверить состояния SOURCE и SINK с помощью мультиметра.
9. Подключить между двумя контактами FPC контрольный резистор, например 1 кОм, после проверки отсутствия коротких замыканий и правильной нумерации разъёма.
10. Выполнить ARM.
11. Выполнить PAIR для этих контактов.
12. Измерить напряжение на R2 и сравнить расчётный ток с показаниями ADC.
13. Проверить отключение после тайм-аута.
14. Проверить команду OFF и ошибки недопустимых параметров.
15. Проверить поведение при Reset во время импульса.

Разделить действия на те, что можно проверить автоматически, и те, которые требуют реального мультиметра или осциллографа.

Не заявлять о прохождении аппаратных испытаний до получения фактических результатов.

После успешного прохождения первого этапа можно будет переходить к исследованию RGB-платы MSI.

## 11. Сборка и тестирование

По окончании работы:

1. Проверить структуру проекта.
2. Выполнить доступные тесты адресации.
3. Выполнить тесты парсера команд, включая ошибочные входные данные.
4. Проверить, что команда OFF приоритетна и отключение по тайм-ауту не зависит от действий USB CDC.
5. Собрать прошивку через доступную STM32 toolchain.
6. Проверить отсутствие компиляционных ошибок и предупреждений, если сборка возможна.
7. Проверить USB CDC-конфигурацию.
8. Проверить, что PA9 не занят функцией VBUS sensing.
9. Проверить, что GPIO управления дешифраторами имеют безопасные начальные состояния.

Если STM32 toolchain или STM32CubeF4 отсутствуют, не подменять сборку фиктивными заглушками и не объявлять её успешной. В таком случае подготовить корректный исходный проект и явно перечислить, какие проверки выполнить на моей машине.

Использовать официальные библиотеки ST, не писать собственный USB-стек.
