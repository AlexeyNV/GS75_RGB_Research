# RGB Vision v0.1 — архитектура и проверка

Актуальное приложение v0.3: [gui_architecture.md](gui_architecture.md),
единый GUI, проекты, фоновые задания, batch и видеокадры. Ниже — история
v0.1/v0.2. [Новые реальные RGB](v03_validation.md).

Модули не зависят от STM32 или COM-порта:

```text
Image -> EXIF / optional undistort -> ArUco -> robust registration
      -> common valid region -> lighting compensation -> optical regions
      -> calibrated LED association / UNKNOWN -> color + quality -> export
```

software/vision/aruco_markers.py — генерация и ID/углы; calibration.py —
проверка JSON и Document с транзакционными изменениями/Undo/Redo;
project_storage.py — относительные пути, hash, изображение и атомарный JSON;
image_registration.py — Registration с REGISTERED/DEGRADED/FAILED;
led_detection.py — чистый фото-pipeline и экспорт; color_detection.py — цвет.
software/gui/ — QGraphicsView, редактор LED, калибратор и окно сравнения.
tools/ содержит отдельные CLI генерации, калибровки и анализа.

Система координат — reference_px. Исходный pixel grid, pixel grid новой
фотографии и эталон связаны H, а не смешиваются с координатами окна.
Физические мм намеренно не объявлены калиброванными. При будущей версии
со шкалой мм понадобится новый явный transform и проверка погрешности.

analyze принимает массивы изображений, analyze_paths — файловую оболочку.
Поэтому позже можно передавать отдельные кадры видео в тот же механизм,
добавив capture timestamp и агрегацию событий. Сейчас MP4/live camera,
захват кадров, motion-blur scoring, временная агрегация и синхронизация
со STM32 не реализованы. Камера не предполагается неподвижной. Нельзя
считать временем свечения дату анализа или момент получения файла.

## Проверено программно

Команда из корня с установленными зависимостями:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py' -v
ctest --test-dir build/host -C Debug --output-on-failure
```

Тесты генератора: 50 распознаваемых ID, уникальность, 8/10/12 наклеек,
10/12/15 мм, габариты A4 и PDF MediaBox, защитное поле, повторяемые байты
PDF/SVG/manifest. GUI: действующий Add LED диалог, zoom/pan и перетаскивание
мышью, поиск/редактирование/удаление/Undo/Redo, карта из 151 GUI-метки и
200 модельных записей, сохранение float без потери, EXIF и checksum,
загрузка 8000×6000, autosave и открытие окна анализа. GUI проверяется
Qt offscreen; читаемые скриншоты сохранены в screenshots/.

Регистрация: перенос, поворот, масштаб, перспектива, частичные маркеры,
недостаток опор, неверные соответствия, зеркало и кластерная геометрия.
На синтетическом наборе максимум ошибки контрольных точек 0,063 px,
RMSE репроекции до 0,146 px. Центр синтетического LED49 при разных ракурсах
OFF/ON локализован с ошибкой 0,039 px. Это не оценка точности настоящей платы.

Детекция: RGB, смешанный цвет, несколько LED, отсутствие свечения и
изменение освещения, белый пересвет, неизвестная область, блик на метке,
отказ геометрии и отсутствие ложного LED ID, безопасная перезапись экспорта.
Синтетические OFF/RED/GREEN/BLUE примеры и три CLI-анализа проверены отдельно.
Предыдущие тесты rgb_probe и схемы остаются в общем наборе.

Тестовое окружение Windows/Python 3.12: OpenCV 4.14.0, PySide6 6.12.0,
NumPy 2.5.5, ReportLab 4.5.1. Точные зависимости сохранены в
requirements-vision-lock.txt. В offscreen Qt при отсутствии перечисленных
шрифтов подгружается доступный системный Segoe UI/Arial/DejaVu Sans;
файлы системных шрифтов не распространяются в репозитории.

## Ограничения

Не проверены печатный лист физической линейкой, распознавание наклеек
на реальной плате и фотоанализ LED49 OFF/RED/GREEN/BLUE. Идеальные
синтетические ошибки не учитывают линзу, блики, параллакс LED, изгиб платы,
движение маркеров, motion blur и баланс белого. Физическая точность мм
не установлена. При сильных нарушениях результат отклоняется, но
локальное отражение вне метки может потребовать ручного отклонения.
Для больших фото память растёт пропорционально числу пикселей; одновременно
в GUI создаётся один pixmap выбранного результата, а не всех режимов сразу.

Исходники и документация используемых API:
[ArUco/OpenCV](https://docs.opencv.org/4.x/d5/dae/tutorial_aruco_detection.html),
[гомография/OpenCV](https://docs.opencv.org/4.x/d1/de0/tutorial_py_feature_homography.html),
[QGraphicsView/Qt](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QGraphicsView.html).

## Актуализация v0.2

Основной pipeline использует optical_signal.py: KNOWN_LEDS и DISCOVER,
новый цветной ореол, причины отбраковки и один статус на LED. color_detection.py
сохранён как исторический классификатор. Реальные OFF/RED и наклейки ArUco
проверены: [результаты](real_validation.md); GREEN/BLUE ещё нужны.
Метрики v0.1 выше исторические; новая синтетическая ошибка центра 0,0712 px.
Проверены 52 Python-тестов, включая реальные фото и GUI. При отсутствии
личных фото два реальных теста явно skip. Печать линейкой в этой работе
не проверялась. Фотоанализ не доказывает аппаратную безопасность PHOTO.
