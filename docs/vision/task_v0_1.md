# GS75_RGB_Research — RGB Vision v0.1: генератор ArUco, графический калибратор и анализ фотографий

Ты опытный Python-разработчик, специализирующийся на OpenCV, PySide6, компьютерном зрении и обработке изображений.

Работаем в существующем проекте:

https://github.com/AlexeyNV/GS75_RGB_Research

Перед началом:
- Изучи `PROJECT_CONTEXT.md`.
- Изучи README и документацию исследования RGB-подсветки.
- Проверь существующий код `tools/rgb_probe.py`.
- Изучи структуру репозитория и текущие Git-изменения.
- Сохрани все существующие фотографии, результаты измерений и пользовательские файлы.

**Не создавай новый репозиторий. Не изменяй прошивку STM32.**

## 1. Цель разработки

Нужно создать программный комплекс, позволяющий:

1. Генерировать компактные ArUco-маркеры для наклеивания на RGB-плату клавиатуры MSI GS75.
2. Открывать высококачественную фотографию платы с наклеенными маркерами.
3. Автоматически находить и идентифицировать маркеры.
4. Вручную указывать координаты светодиодов щелчками мыши.
5. Присваивать каждому светодиоду номер `LED_ID` и название соответствующей клавиши.
6. Сохранять эталонную карту расположения всех светодиодов.
7. Открывать другие фотографии той же платы с любого допустимого ракурса.
8. Автоматически определять положение платы по ArUco и пересчитывать координаты LED.
9. Сравнивать фотографии выключенной и включённой подсветки.
10. Определять, какие LED загорелись и каким цветом.

Программа должна быть пригодна для дальнейшего подключения офлайн-видеозаписей и живой камеры.

**Текущий этап — только ArUco, графический калибратор и анализ фотографий. Обработку видео и синхронизацию со STM32 пока не реализовывать.**

## 2. Технологии

Использовать:

- Python 3.
- PySide6 для графического интерфейса.
- OpenCV с модулем `cv2.aruco`.
- NumPy.
- JSON для конфигураций.
- CSV/JSON для результатов.
- SVG и при необходимости PDF для печати маркеров.
- pytest или unittest для автоматических тестов.

Для высокоразрешённых изображений использовать `QGraphicsView` / `QGraphicsScene`, позволяющие масштабировать и перемещать изображение без изменения его исходных координат.

Не делать графический интерфейс через набор вызовов `cv2.imshow()`.

## 3. Генератор ArUco-маркеров

Создать инструмент:

`tools/generate_markers.py`

Использовать словарь:

`DICT_4X4_50`

Предусмотреть:

- Генерацию 8–12 уникальных маркеров.
- Настраиваемые ID.
- Размер наклейки по умолчанию 10×10 мм.
- Дополнительные размеры 12×12 и 15×15 мм.
- Белое защитное поле вокруг чёрного кода.
- Печать на A4 в масштабе 100%.
- Контрольную линейку длиной 50 мм.
- Линии разреза наклеек.
- Отдельную подпись номера каждого маркера на печатном листе.

Важно: если размер наклейки задан как 10 мм, он должен учитывать защитное белое поле. Нельзя незаметно увеличить физические размеры наклейки.

Подпись ID не должна нарушать структуру ArUco и попадать внутрь защитной области. При необходимости вынести подпись за линию разреза.

Сформировать:

```text
build/markers/
  aruco_A4.pdf
  aruco_A4.svg
  markers_manifest.json
  individual/
    marker_00.png
    marker_01.png
    ...
```

Файлы PNG должны быть пригодны для проверки алгоритма, а PDF/SVG — для физической печати.

После генерации автоматически проверить, что OpenCV правильно распознаёт каждый созданный маркер.

Добавить инструкцию:
- Как печатать без масштабирования.
- Как проверить линейкой реальный размер.
- Как наклеивать маркеры.
- Как избежать перекрытия светодиодов, дорожек и тестовых площадок.
- Почему предпочтительны матовые наклейки.

Размер 10 мм считать экспериментальным: при недостаточном качестве распознавания предложить 12–15 мм.

## 4. Графический калибратор платы

Создать основное приложение:

`tools/board_calibrator.py`

Это главный результат текущего этапа.

### 4.1. Загрузка изображения

Калибратор должен открывать фотографии JPG, JPEG, PNG, TIFF.

Поддержать большие изображения, например:
- 4000×3000;
- 6000×4000;
- 8000×6000.

При открытии показывать реальное разрешение изображения.

Изображение должно отображаться в центральной области окна.

Обязательные функции:
- Масштабирование колесом мыши.
- Перемещение изображения мышью.
- Fit to Window.
- Масштаб 100%.
- Масштаб 200%, 400% и выше.
- Просмотр координат пикселя под курсором.
- Корректная работа со скроллингом и масштабированием.

Координаты LED должны храниться относительно исходного изображения, а не относительно окна программы.

Изменение размера окна или масштаба не должно изменять координаты светодиодов.

### 4.2. Распознавание ArUco

При открытии изображения:

1. Обнаружить ArUco.
2. Определить ID каждого маркера.
3. Получить координаты четырёх углов.
4. Отобразить контуры обнаруженных маркеров.
5. Показать их ID на изображении.
6. Вывести количество распознанных маркеров.

Добавить возможность скрывать или показывать разметку ArUco.

Если часть маркеров не распознана, вывести соответствующее предупреждение, но не препятствовать сохранению корректных данных остальных маркеров.

Сохранить координаты углов каждого маркера в эталонной системе координат платы.

Не предполагать, что маркеры всегда расположены строго горизонтально.

### 4.3. Разметка светодиодов мышью

Создать режим:

`Add LED`

При выборе режима пользователь кликает на изображении по центру светодиода.

Программа:
1. Регистрирует координаты точки.
2. Ставит хорошо видимый маркер поверх изображения.
3. Открывает небольшую панель редактирования.
4. Позволяет указать номер светодиода.
5. Позволяет указать название клавиши.
6. Сохраняет запись в текущем проекте калибровки.

Предусмотреть поля:

**LED ID:**
- LED1
- LED2
- ...
- LED49
- ...

**Key Name:**
- A
- B
- C
- F1
- Esc
- Space
- LeftShift
- RightCtrl
- Enter
- и любые другие пользовательские значения.

Не придумывать соответствие LED номеру клавиши автоматически.

LED ID и Key Name должны быть независимыми сущностями.

Название клавиши может отсутствовать, если соответствие ещё неизвестно.

Разрешить несколько LED для одной клавиши.

LED ID должен оставаться уникальным внутри карты.

### 4.4. Редактирование данных

После добавления LED пользователь должен иметь возможность:

- Выбрать LED на изображении.
- Изменить LED ID.
- Изменить название клавиши.
- Переместить точку.
- Удалить точку.
- Отменить последнее действие.
- Вернуть отменённое действие.
- Отобразить и скрыть подписи.
- Перейти к выбранному LED из списка.
- Найти LED по номеру или названию клавиши.

Подписи не должны полностью закрывать соседние светодиоды.

При большом количестве меток предусмотреть ограничение плотности подписей или их отображение только при выборе.

### 4.5. Панель списка LED

Добавить справа таблицу:

| LED ID | Key Name | X | Y |
|---|---|---|---|
| LED49 | — | ... | ... |

При клике на строку:
- Подсветить соответствующий светодиод.
- Центрировать изображение на нём.
- Позволить изменить запись.

При наведении на LED в изображении показывать его ID, название клавиши и координаты.

Добавить сортировку и поиск по таблице.

### 4.6. Удобство разметки

Разметка может содержать больше сотни светодиодов. Поэтому важны:

- Быстрое добавление следующего LED.
- Запоминание ранее введённого названия или шаблона имени.
- Настраиваемый размер маркера.
- Горячие клавиши.
- Автоматическое сохранение черновика.
- Предупреждение при закрытии с несохранёнными изменениями.
- Undo/Redo.

При этом запрещено автоматически назначать следующим светодиодам номера на основании их позиции, если это может создавать ошибочные соответствия с маркировкой PCB.

Автонумерация допустима только как явно включаемый режим.

## 5. Система координат

Нужно чётко разделить:

1. Координаты пикселя исходной фотографии.
2. Эталонные координаты платы.
3. Координаты пикселя новой фотографии.
4. Физические координаты в миллиметрах, если они достоверно откалиброваны.

Для первой версии допустимо использовать систему координат эталонной фотографии.

Обязательно сохранить её размеры и ориентацию.

Однако архитектура должна позволять впоследствии перейти к координатам платы в миллиметрах.

Нельзя объявлять координаты в миллиметрах физически точными только потому, что программа знает номинальный размер напечатанного маркера. Требуются проверка фактического размера, геометрии и погрешности преобразования.

Привязку между системами координат выполнять по уникальным ArUco ID и известным углам маркеров.

## 6. Формат сохранения калибровки

Предусмотреть JSON-файл калибровки, например:

`config/gs75_board_calibration.json`

Он должен содержать:
- Версию схемы файла.
- Путь к эталонной фотографии относительно корня проекта.
- Разрешение фотографии.
- Контрольную сумму эталонной фотографии.
- Словарь ArUco.
- IDs маркеров.
- Координаты их углов.
- Размеры наклеек.
- Систему координат.
- Список всех LED.
- Названия клавиш.
- Метаданные и комментарии пользователя.

Пример записи LED:

```json
{
  "led_id": "LED49",
  "key_name": null,
  "x_ref_px": 1842.6,
  "y_ref_px": 1013.2,
  "note": "RGB confirmed electrically"
}
```

Координаты в примере условные. Соответствие LED49 конкретной клавише ещё не установлено.

Сохранять конфигурацию без потери точности.

Предусмотреть проверку валидности данных при повторном открытии.

Использовать относительные пути для переносимости проекта между компьютерами.

## 7. Анализ новых фотографий

Создать режим:

`Analyze Images`

Пользователь открывает:
- Снимок платы с выключенной подсветкой — OFF.
- Снимок с включённой подсветкой — ON.

Фотографии могут быть сделаны с разных ракурсов и с разным положением камеры.

**Нельзя просто вычитать изображения без предварительного геометрического совмещения.**

### 7.1. Геометрическая регистрация

Для каждого изображения отдельно:

1. Найти ArUco-маркеры.
2. Определить соответствие их ID эталонной карте.
3. Найти преобразование из текущего изображения в координаты платы.
4. Использовать робастную оценку гомографии.
5. Преобразовать изображение к эталонной геометрии.
6. Проверить ошибку репроекции и допустимость геометрии.

Использовать `cv2.findHomography()` и `cv2.warpPerspective()` либо эквивалентные проверенные методы.

Если параметры объектива известны, добавить возможность коррекции дисторсии до расчёта гомографии.

При сильном искажении, отсутствии маркеров или ошибочной геометрии не формировать ложные результаты.

Предусмотреть статусы:
- REGISTERED
- DEGRADED
- FAILED

Использовать несколько пространственно разнесённых маркеров для надёжности, предпочтительно не менее трёх.

### 7.2. Анализ свечения

После регистрации OFF и ON:

1. Определить общую область, корректно видимую на обеих фотографиях.
2. Компенсировать небольшие различия освещения.
3. Вычислить разность.
4. Найти локальные области нового свечения.
5. Определить координаты и цветовые характеристики.
6. Сопоставить обнаруженные области с эталонными координатами LED.
7. Вернуть LED ID и название клавиши.

Поддержать:
- Красный.
- Зелёный.
- Синий.
- Смешанные цвета.
- Неопределённый цвет.

Не классифицировать пересвеченные белые пятна принудительно как конкретный цвет.

Если светится несколько LED, регистрировать все найденные светодиоды.

Если световая область не совпадает ни с одним известным LED, пометить её как неизвестную и предложить добавить новый LED в калибратор.

### 7.3. Просмотр результатов

В графическом интерфейсе показать:
- Исходную OFF-фотографию.
- Исходную ON-фотографию.
- Совмещённые изображения.
- Изображение разности.
- Найденные светящиеся LED.
- Их имена и цветовые характеристики.
- Оценку качества регистрации.

Дать возможность переключать изображения и включать/выключать наложение.

Результаты должны позволять вручную проверить корректность обнаружения.

- Имя анализируемой фотографии.

- Дата анализа.
- LED ID.
- Название клавиши.

- Площадь светящейся области.

## 9. Работа с LED49

Для первого практического эксперимента используем уже исследованный светодиод LED49.

Подтверждённая электрическая карта:

- A = KP14.
- R = KP32, 100 Ом.
- G = KP33, 16 Ом.
- B = KP34, 75 Ом.

При испытании FW 0.1.1:
- RED: 1033 мкА.
- GREEN: 886 мкА.
- BLUE: 794 мкА.

Каждая комбинация зажигала только LED49.

Нужно подготовить возможность загрузить четыре фотографии:
- LED49 OFF.
- LED49 RED.
- LED49 GREEN.
- LED49 BLUE.

После калибровки программа должна корректно находить LED49 на каждой фотографии и распознавать цвет, даже если камера находилась под другим углом.

Не объявлять этот тест пройденным, пока не получены реальные фотографии и результат их анализа.

## 10. Перспектива офлайн-видео

В текущей версии видео НЕ реализовывать.

Но структура должна позволять в следующем этапе подавать в тот же механизм изображения кадров MP4.

Модель должна поддерживать:

`Image → ArUco → Geometry Registration → LED Detection → Optical Result`

Для видео этот pipeline будет выполняться заново на каждом кадре.

Не делать архитектуру, требующую неподвижной камеры.

Заранее учитывать:
- Временные метки кадров.
- Перемещение камеры.
- Исчезновение маркеров.
- Кадры с motion blur.
- Агрегацию последовательных обнаружений в события.

Не реализовывать эти функции сейчас, если они не требуются для фотоанализа.

## 12. Тестирование

Создать автоматизированные тесты.

### Генерация

- Все маркеры имеют уникальные ID.
- OpenCV распознаёт каждый маркер.
- Размеры печатной страницы корректны.
- Расположение не нарушает границы A4.
- Результат воспроизводим при повторном запуске.

### Калибратор

- Корректное преобразование координат курсора при масштабировании.
- Корректное преобразование при перемещении изображения.
- Сохранение и восстановление координат LED.
- Редактирование LED.
- Удаление LED.
- Undo/Redo.
- Обработка дублирующегося LED ID.
- Работа с несколькими LED у одной клавиши.
- Сохранение большого набора точек.

### Регистрация изображений

Синтетически создать изображения с:
- Сдвигом.
- Поворотом.
- Масштабированием.
- Перспективным искажением.
- Различным освещением.
- Частично скрытыми маркерами.
- Недостаточным количеством опорных точек.

Проверить точность возвращения точек к эталонным координатам.

Вывести численные ошибки локализации в пикселях.

### Распознавание LED

Создать синтетические снимки OFF/ON для LED49.

Проверить:
- Красный.
- Зелёный.
- Синий.
- Несколько светодиодов.
- Отсутствие свечения.
- Пересвет.
- Отражение от метки.
- Ошибку геометрической регистрации.

В случае неудачной регистрации система должна сообщать о невозможности достоверного анализа, а не возвращать выдуманный LED ID.
