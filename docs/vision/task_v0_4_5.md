# GS75_RGB_Research — v0.4.5: восстановление коротких оптических событий и исправление сопоставления с STM32

Работаем в существующем репозитории GS75_RGB_Research, текущая версия v0.4.4, коммит 5799a53.

## Цель

Исследовать результаты первого **реального аппаратного короткоимпульсного эксперимента** LED49 RED и устранить избыточную фрагментацию оптических событий и проблемы сопоставления.

Не менять прошивку STM32 и не запускать аппаратный стенд.

## 2. Исследование первопричины

Для всех 30 электрических операций сформировать диагностическую таблицу с:

- ID операции.
- Временным окном TX/ACK/DONE.
- Соответствующими PTS видео.
- Состояниями LED49 каждого кадра.
- Качеством геометрии.
- Валидностью OFF-фона и локального ROI.
- RGB-сигналом.
- Уверенностью классификации.
- Причинами UNKNOWN/INVALID_GEOMETRY.
- Результатом TemporalDetector.
- Результатом matcher.

Особенно исследовать операции № 4, 12, 13, 14, 16, 18, 22 и 27.

Предварительно показано, что для каждой из этих операций есть оптические признаки, но алгоритм не всегда объединяет их в одно подтверждённое событие.

Установить, какие именно критерии приводят к разделению или отклонению.

Не считать все визуальные фрагменты истинными автоматически.

## 3. Исследование временной непрерывности

Проверить механизм:
- Кратковременной потери наблюдений.
- Гистерезиса ON/OFF.
- Подтверждения ON.
- Подтверждения OFF.
- Завершения события при UNKNOWN.
- Объединения соседних фрагментов.
- Учёта фактических PTS.

Различать:
- Подтверждённый OFF между событиями.
- Недостоверный кадр внутри возможного свечения.
- Одно событие, разделённое потерей достоверности.
- Два разных электрических импульса.

Не объединять два включения через подтверждённый OFF.

Если событие объединяется через UNKNOWN, сохранять неопределённость непрерывности и не представлять гипотезу как непрерывное подтверждённое свечение.

## 4. Повторная обработка и сопоставление

Сначала независимо от журнала STM32 восстановить оптические события.

Затем сопоставить их с электрическими операциями.

Проверить оценку временного смещения между host TX и PTS: предварительно около −1,81 с.

Это лишь диагностическая оценка, не аппаратная синхронизация.

Реализовать возможность связывания нескольких временных фрагментов одного физического LED с одной электрической операцией без потери исходных записей.

При этом сохранить поддержку ситуации, когда одна электрическая пара действительно включает несколько разных LED.

Не использовать ожидаемые 30 импульсов как условие принудительного подтверждения всех событий.

Не повышать confidence исключительно на основании совпадения с журналом STM32.

Разрешить оператору вручную подтверждать неоднозначные соответствия.

## 5. Диагностика неизвестных интервалов

На реальном видео зарегистрированы многочисленные интервалы UNKNOWN.

Добавить статистику отдельно по причинам:

- Потеря ArUco.
- Неудовлетворительная гомография.
- Недостаточное покрытие ROI.
- Низкий цветовой сигнал.
- Неоднозначность цвета.
- Потеря временной непрерывности.
- Иные причины.

Указать точные количества кадров и интервалов по каждой причине.

Не смешивать недостаток достоверности геометрии с отсутствием свечения.

30/30 не является обязательным условием успешной реализации. Успехом считается корректная классификация и объяснение каждого случая без ложной уверенности.

Проверить отрицательные случаи:

- Реальный OFF между импульсами.
- Кратковременные блики.
- Пропущенные кадры.
- Потеря ArUco.
- Видео без включений.
- Неоднозначная синхронизация.
