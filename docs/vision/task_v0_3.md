# GS75_RGB_Research — RGB Vision v0.3: единое GUI-приложение, импорт фото/видео и анализ RGB

Ты — опытный Python-разработчик систем машинного зрения, GUI на PySide6, OpenCV и инженерного ПО.

Работаем в существующем репозитории:

https://github.com/AlexeyNV/GS75_RGB_Research

Главная цель — превратить существующий калибратор и анализатор в **единое удобное графическое приложение**, которым пользователь сможет управлять полностью через интерфейс Windows, без ручного ввода команд Python.

## 2. Новая концепция программы

Название: **GS75 RGB Vision**.

Вся работа с изображениями должна выполняться через единый GUI.

Пользователь должен иметь возможность:

1. Открыть существующий проект исследования RGB-платы.
2. Создать новый проект.
3. Загрузить эталонную фотографию.
4. Открыть и изменить карту светодиодов.
5. Добавлять LED с помощью мыши и присваивать им названия клавиш.
6. Загружать отдельные фотографии и целые группы изображений.
7. Загружать видеофайлы.
8. Выбирать изображения OFF и ON.
9. Запускать анализ кнопкой.
10. Просматривать результаты, найденные светодиоды, цвета и координаты.
11. Сохранять результаты и диагностические изображения.
12. Повторно открывать ранее проведённые эксперименты.

Командная строка остаётся как вспомогательный интерфейс для тестирования, но **не должна требоваться в обычной работе**.

Приложение должно запускаться одним действием через отдельный Windows launcher, например `Start_RGB_Vision.bat`, с использованием существующего виртуального окружения.

Предпочтительно предусмотреть запуск через `pythonw.exe`, без постоянно открытого окна терминала. Ошибки показывать в приложении и записывать в лог.

## 4. Удобный импорт фотографий

Сейчас пользователь вынужден выполнять:

```powershell
python tools/analyze_images.py --calibration ... --off ... --on ... --output ...
```

Такого требования больше быть не должно.

Создать интерфейс импорта:

**Добавить фотографии**

При нажатии открывается обычное окно выбора файлов Windows.

Поддержать:
- JPG/JPEG.
- PNG.
- TIFF.
- Одновременный выбор нескольких файлов.
- Drag & Drop из Проводника Windows.

После импорта фотографии отображаются миниатюрами.

Пользователь назначает снимкам роли:

- REFERENCE — эталон калибровки.
- OFF — подсветка выключена.
- ON — подсветка включена.
- UNASSIGNED — роль не определена.

Изменять роль можно через контекстное меню или панель свойств.

Приложение должно автоматически предлагать выбранную ранее эталонную карту, но не подменять её молча.

Для тестового комплекта:

```text
data/
  off.jpg
  red.jpg
  green.jpg
  blue.jpg
```

Пользователь должен иметь возможность выбрать все четыре файла одновременно, назначить `off.jpg` как OFF, остальные как ON и нажать:

**Анализировать выбранные изображения**

Программа выполняет три независимых сравнения:

- OFF / RED.
- OFF / GREEN.
- OFF / BLUE.

И показывает общий результат.

Нельзя автоматически считать правильным цвет на основании имени файла.

## 5. Пакетный анализ

Реализовать Batch Analysis.

Сценарий:

1. Пользователь выбирает одну OFF-фотографию.
2. Выбирает несколько ON-фотографий.
3. Нажимает «Анализировать».
4. Программа обрабатывает изображения последовательно.
5. В интерфейсе появляется таблица результатов.

Пример:

| Файл | LED | Статус | Цвет |
|---|---|---|---|
| red.jpg | LED49 | ON | RED |
| green.jpg | LED49 | ON | GREEN |
| blue.jpg | LED49 | ON | BLUE |

Это ожидаемое поведение после исправления классификатора, а не результат, который можно заранее подставить.

Для каждого изображения сохранять отдельный отчёт, а также общий CSV/JSON пакетной обработки.

Поддержать отмену обработки и отображение прогресса.

## 7. Режимы обнаружения

В интерфейсе предусмотреть переключатель:

### KNOWN_LEDS

Анализ известных светодиодов из калибровки.

Показывать состояния:
- ON.
- OFF.
- UNCERTAIN.
- Геометрическая регистрация не выполнена.

### DISCOVER

Поиск светящихся областей, ещё не связанных с LED ID.

Найденные области отображать на изображении.

Пользователь должен иметь возможность:

1. Выбрать обнаруженную область мышью.
2. Посмотреть увеличенный участок.
3. Указать PCB LED ID.
4. Назначить название клавиши, если оно известно.
5. Добавить новый LED в карту калибровки.

Не назначать LED ID автоматически без подтверждения пользователя.

Предусмотреть предотвращение дубликатов.

Это особенно важно для дальнейшего исследования всей RGB-платы.

## 8. Исправление ошибки BLUE → MIXED

В реальном испытании FW 0.1.2 получены фотографии:

- `data/off.jpg`
- `data/red.jpg`
- `data/green.jpg`
- `data/blue.jpg`

Текущий алгоритм определяет:

- RED → LED49 ON RED.
- GREEN → LED49 ON GREEN.
- BLUE → LED49 ON MIXED.

Реальный синий канал подтверждён аппаратно.

Средний положительный RGB-сигнал для BLUE:

```text
R = 6.162
G = 37.196
B = 134.475
```

Проанализировать причину `MIXED`.

Улучшить классификатор так, чтобы:
- Учитывался доминирующий цветовой компонент.
- Побочный отклик соседних каналов камеры не считался автоматически вторым источником света.
- Пересвеченное белое ядро не искажало оценку цвета.
- Поддерживались настоящие смешанные цвета.
- Неоднозначные ситуации оставались UNCERTAIN.
- Не использовались жёсткие координаты LED49 или имена файлов.

Сохранить существующие успешные результаты RED и GREEN.

В JSON записывать метрики цветовой уверенности и причины классификации.

## 9. Просмотр результатов анализа

Создать единый визуальный просмотрщик.

Пользователь выбирает эксперимент и может переключаться между слоями:

- Original OFF.
- Original ON.
- Registered OFF.
- Registered ON.
- Difference.
- Color mask.
- Detected LEDs.
- Rejected candidates.
- ArUco markers.

При выборе светодиода в таблице приложение центрирует изображение на соответствующей точке и увеличивает ROI.

При выборе LED на изображении выделяется его строка в таблице.

В таблице показывать:

- LED ID.
- Название клавиши.
- ON/OFF.
- Цвет.
- Координаты.
- Яркость.
- Цветовой сигнал.
- Статус регистрации.
- Степень уверенности или признаки неоднозначности.

Пользователь должен видеть ошибки и причины отказа, а не только сообщение «не обнаружено».

## 10. Загрузка видеозаписей

Реализовать **первый этап поддержки видео в этом же приложении**.

Поддержать импорт:
- MP4.
- MOV, если поддерживается установленным декодером.
- AVI, если поддерживается установленным декодером.

В разделе «Видео»:

1. Кнопка «Открыть видео».
2. Отображение видеозаписи.
3. Play/Pause.
4. Ползунок перемотки.
5. Переход на следующий/предыдущий кадр.
6. Отображение времени и номера кадра.
7. Кнопка «Использовать кадр как OFF».
8. Кнопка «Использовать кадр как ON».
9. Кнопка «Сохранить кадр».
10. Возможность отправить выбранные кадры непосредственно в фотоанализатор, без ручного сохранения на диск.

При выборе кадров использовать доступные временные метки декодера. Учитывать возможность переменной частоты кадров; если точное время неизвестно, показывать это как ограничение.

Не загружать всё видео целиком в оперативную память.

Не блокировать GUI при декодировании.

### Важно: полный анализ видео — следующий этап

На текущем этапе достаточно:
- Импорта видеозаписи.
- Просмотра.
- Выбора кадров.
- Анализа выбранных OFF/ON кадров через существующий pipeline.

Но архитектуру нужно подготовить для дальнейшего автоматического анализа каждого кадра.

Будущий алгоритм должен повторно определять ArUco на каждом кадре, поскольку смартфон может двигаться во время видеосъёмки.

**Нельзя считать, что одна гомография подходит для всего видео.**

Не заявлять, что полноценный анализ видеозаписи реализован, если пока доступен только выбор отдельных кадров.

**Этап A — единый интерфейс и проект.**

**Этап B — удобный импорт и пакетный анализ.**

**Этап D — видеоимпорт.**

**Этап E — тестирование и документация.**

Проверить GUI, Python-тесты, реальные изображения и обновить контекст проекта.
