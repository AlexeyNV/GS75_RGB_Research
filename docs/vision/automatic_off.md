## Сценарий GUI

1. Start_RGB_Vision.bat → открыть проект с картой и доступным эталоном.
2. «Производительность видео» → выбрать MP4. Здесь display 1080×1920,
   coded 1920×1080, rotation −90°, поток 30,818 с, контейнер 30,892 с.
   Разница связана со стартовым PTS. Кадры не пересчитываются в условные 30 FPS.
3. Источник «Автоматический OFF из интервала», начало 0, длительность 2 с.
   Для этого файла начальный интервал действительно без RGB-свечения;
   на других записях интервал должен подтвердить оператор.
4. «Построить OFF». Поиск/медиана работают в worker. На этом файле выбрано
   5 наблюдений, LED49 coverage 94,24%. Без экспорта построение заняло
   9,12 с; с GUI/экспортом/профайлером примерно 13 с.
5. «Диагностика OFF: кадры и покрытие». Таблица показывает frame/PTS,
   причину, выбран/не выбран, RMSE, raw/stable/smooth доли изменений.
   ELIGIBLE означает качество пройдено, выбран=True — попадание в медиану.
6. Выбрать строку и слой: исходный кадр, ArUco, warp, valid/common mask,
   разность до/после компенсации, сглаженный остаток, >40 mask, цветные
   области. Есть zoom/pan и открытие каталога со всеми файлами.
7. На карте красным затемнены недостоверные области. Геометрическое
   покрытие оценённого контура PCB 73,21%; после ArUco/quiet zones для
   DISCOVER недоступно 28,99% PCB. LED49 — дисковый ROI радиуса 40 ref px,
   требуется ≥90%. Полное покрытие неизвестных LED не утверждается.
8. При отказе прочитать причину, открыть диагностику, изменить интервал,
   проверить резкость/ArUco. Ошибка/отмена не оставляют 100% или успешный
   OFF. Полный traceback сохраняется в logs/rgb_vision.log. Экспорт доступен
   и без успешного benchmark — он сохраняет диагностический каталог.
9. Альтернатива: назначить одно OFF-фото проекту и явно выбрать источник
   «Назначенное OFF-фото проекта». Переключение не автоматическое;
   покрытие известных LED проверяется и для фотографии.
10. Для первого замера выбрать C_HYBRID и 120 кадров, затем 0 («Всё видео»).
    Режим KNOWN_LEDS/DISCOVER выбирается прежним переключателем приложения.
    DISCOVER скрывает координаты LED после проверки OFF. Все 4 архитектуры
    тоже доступны, но на grid 4000×2256 полноразмерные варианты очень дороги.
11. Измерить и экспортировать. Все 922 кадра обработаны: KNOWN около
    21,26 FPS, blind DISCOVER 12,84 FPS; источник около 29,92 FPS.
    **Реальные 30 FPS не достигнуты.**

В обычном Windows GUI проверены build OFF, просмотр диагностики,
KNOWN/DISCOVER по 120 кадров и экспорт. Полные 922 — общий benchmark API.

## Алгоритм и безопасность качества

Legacy сравнивал четыре образца с первым кадром по абсолютной разности
каналов. Локальное смещение белой шелкографии на пару reference px давало
>40 на узких краях и превышало 2%, хотя LED был выключен. Первый legacy-
кадр также не покрывал LED49. Точные причины кадров 13/28/43 — в отчёте.

Новая версия ищет ≤24 кандидатов по всему интервалу, хранит ≤5 лучших
наблюдений плюс текущий кадр. Каждый имеет независимые ArUco/H. Выбор
учитывает покрытие ROI, RMSE, видимость и резкость. Исходные допуски
регистрации сохранены; DEGRADED с двумя метками не подтверждает видеособытие.

Разделены проверки:

- Абсолютное локальное RGB-свечение: постоянно включённый LED нельзя
  принять за OFF только потому, что разность с первым кадром нулевая.
- Поканальная affine-компенсация: gain 0,7…1,3, offset ±35 как раньше.
- Residual >40 / доля >2% в стабильных областях без узких контрастных
  границ и по низкочастотным структурам. Пороги не повышены.
- Blur, общая область, покрытие ROI. Обнаруженное свечение/перекрытие/
  существенная смена света отвергают весь интервал, даже если ранее
  накопились три хороших кадра.

Медиана считается поканально по valid-наблюдениям, плитками 64 строки.
Пиксель требует ≥3 и ≥80% выбранных кадров (для 5 — минимум 4).
За пределами valid может сохраняться preview для просмотра/ArUco baseline;
**оно не участвует в анализе**, mask применяется во всех видеоархитектурах.
KNOWN ROI с coverage<90% не допускает успешную модель.

Вместо np.nanmedian — сортировка uint16 с sentinel 256 и выбором рангов по
числу наблюдений. Это та же целочисленная медиана, включая чётные counts,
без миллионов all-NaN предупреждений на закрытых маской пикселях.
Равенство проверено случайными плитками и побитно на настоящей модели.

Каждый benchmark содержит полный JSON, frames.csv, Markdown и график.
GUI сохраняет диагностику в новый UUID-каталог reports_dir проекта также
при ошибке/отмене. Экспорт существующие каталоги не перезаписывает.
В Git — компактные числовые материалы, код и документация. Медиа и большие
карты остаются локальными; для другого ПК переносить data/ и нужный build/ отдельно.

CLI не обращается к COM; все output-каталоги должны быть новыми:

```powershell
.\.venv\Scripts\python.exe tools/diagnose_off_video.py --video data/VID_20261117_101549.mp4 --frames 0,13,28,43,59 --output build/new_off_diagnostics
.\.venv\Scripts\python.exe tools/benchmark_video.py --video data/VID_20261117_101549.mp4 --variant C_HYBRID --mode KNOWN_LEDS --frames 120 --output build/new_known_120
.\.venv\Scripts\python.exe tools/benchmark_video.py --video data/VID_20261117_101549.mp4 --variant C_HYBRID --mode KNOWN_LEDS --frames 0 --output build/new_known_full
.\.venv\Scripts\python.exe tools/benchmark_video.py --video data/VID_20261117_101549.mp4 --variant C_HYBRID --mode DISCOVER --blind-discover --frames 0 --output build/new_discover_full
```

Diagnostic-only CLI не строит OFF-модель. Для исходного отказа использован
код 33ecde1; числа сохранены в отчёте. Новая display orientation и иной
набор RANSAC inliers могут менять конкретные принятые номера кадров;
проверяется качество, а не заранее заданный список.

## Ограничения

Это не production-анализ/точная синхронизация. EventAggregator даёт
фрагменты; на OFF остаются UNCERTAIN из-за ахроматических краёв; DISCOVER
имеет лишние неизвестные кандидаты. B иногда теряет ROI, где C получает
хорошую геометрию. Один вариант не получает PASS за сравнение с собой.

Границы RGB ограничены соседними PTS, не плановыми временами. Экспозиция,
rolling shutter и связь с CDC оставляют неопределённость; UNALIGNED сохранён.
PCB contour не ручной ground truth. Слабое/скрытое свечение, нейтральное
статическое перекрытие и короткие события между кандидатами универсально
не исключаются. OFF не доказывает электрическое отключение. Video-specific
intrinsics ещё не валидированы; camera_model требуется null.
