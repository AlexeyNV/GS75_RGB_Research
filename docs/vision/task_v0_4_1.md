## 1. Цель

Реализовать в существующем графическом приложении GS75 RGB Vision полностью автоматизированный **эксперимент по последовательному включению LED49**, предназначенный для записи тестового видео на внешний смартфон Redmi Note 11 Pro.

Оператор будет снимать RGB-плату на смартфон, а приложение автоматически управлять подсветкой через USB CDC STM32.

Оператор должен выполнить всего четыре действия:

1. Подключить STM32 к компьютеру.
2. Открыть вкладку «Видеоэксперимент» и подключиться к COM-порту.
3. Запустить видеозапись на смартфоне.
4. Нажать «Запустить эксперимент».

После этого приложение самостоятельно выполняет заданную последовательность OFF / RED / GREEN / BLUE / OFF, сохраняет электрические измерения и журнал времени.

**Весь эксперимент должен выполняться через GUI, без PowerShell, PuTTY и ручного ввода команд.**

Не создавать отдельную программу, если функциональность можно интегрировать в уже существующий интерфейс.

## 3. Проверенные возможности FW 0.1.2

Поддерживаемые команды:

```text
PING
INFO
STATUS
ADCSTATUS
SELFTEST
ARM 20
PHOTO LED49 RED 5000
PHOTO LED49 GREEN 5000
PHOTO LED49 BLUE 5000
OFF
```

PHOTO поддерживает длительности 100–10000 мс.

Разрешены только:

| Цвет | SOURCE | SINK | Измеренный средний ток |
|---|---|---|---|
| RED | KP14 | KP32 | 1035 мкА |
| GREEN | KP14 | KP33 | Ранее около 886 мкА |
| BLUE | KP14 | KP34 | 797 мкА |

RED аппаратно проверен до 10000 мс, BLUE — на 1000 мс, GREEN визуально подтверждён.

Предел тока защиты — 2000 мкА, допустимый возраст ADC — 5 мс.

Прошивка самостоятельно ограничивает длительность PHOTO. ARM действует ограниченное время. Команда OFF должна отключать выходы немедленно.

**IWDG не включён.** Поэтому стенд нельзя объявлять аппаратно отказоустойчивым к зависанию MCU. Оператор должен иметь возможность физически снять питание.

Не расширять длительный режим PHOTO на неизвестные LED или произвольные контакты.

## 5. Сценарий эксперимента

Реализовать предустановленный сценарий:

`LED49_RGB_VIDEO_TEST`

| № | Состояние | Продолжительность |
|---|---|---:|
| 1 | OFF — получение начального фона | 5000 мс |
| 2 | LED49 RED | 5000 мс |
| 3 | OFF | 3000 мс |
| 4 | LED49 GREEN | 5000 мс |
| 5 | OFF | 3000 мс |
| 6 | LED49 BLUE | 5000 мс |
| 7 | OFF — завершающий фон | 5000 мс |

Плановая суммарная продолжительность — 31000 мс, без учёта задержек обмена и переходов между стадиями.

Паузы OFF и длительности PHOTO должны быть настраиваемыми в GUI в пределах безопасных ограничений прошивки.

Начальный OFF по умолчанию 5 секунд. Для проверки автоматического построения фоновой модели должно быть достаточно времени до первого свечения.

Не включать LED автоматически при открытии программы или подключении COM-порта.

### Порядок исполнения

После нажатия «Запустить»:

1. Повторно проверить состояние STM32.
2. Показать сообщение о необходимости начать запись видео на телефоне.
3. После явного подтверждения пользователя начать первый интервал OFF.
4. Перед каждым PHOTO выполнить отдельный ARM с достаточным, но ограниченным временем.
5. Отправить PHOTO.
6. Дождаться ACK соответствующей операции.
7. Дождаться DONE с тем же ID.
8. Проверить REASON, FAULT, измеренный ток и фактическую длительность.
9. Выполнить OFF и подтвердить отключённые EN.
10. Выдержать предусмотренную паузу.
11. Перейти к следующему цвету только после успешного завершения предыдущего.
12. По окончании выполнить OFF, STATUS и сохранить журнал.

Для первой OFF-стадии и промежуточных OFF-пауз не нужен ARM.

Для управления задержками на стороне ПК использовать монотонные часы, не `time.sleep()` в GUI-потоке.

**Не запускать следующий PHOTO, пока предыдущий не завершился подтверждённым DONE.**

Не пытаться создать непрерывное 5-секундное свечение серией PAIR.

PHOTO выполняется одной командой MCU.

### Временная схема

В журнале записывать плановые и фактические времена этапов отдельно.

В частности, не считать номинальные границы 5, 10, 13 секунд точными границами реального включения.

Каждый переход должен иметь собственную временную метку.

## 6. Безопасность управления

Добавить обязательные проверки:

- U13 OPEN — подтверждается оператором вручную.
- R1=2700 Ом — подтверждается оператором вручную.
- Подключена именно исследуемая RGB-плата.
- STM32 физически доступен для отключения питания.
- Оператор присутствует во время эксперимента.

ПО не может определить положение U13 только по ответу ADC, поэтому не выдавать программное подтверждение за аппаратную проверку.

Перед запуском показывать компактный диалог подтверждения условий.

### Прерывание эксперимента

Кнопка «Прервать / OFF» должна:

1. Немедленно прекратить планирование новых операций.
2. Отправить OFF на доступный COM-порт, не ожидая завершения текущего PHOTO.
3. Получить подтверждение выключения, если связь исправна.
4. Записать причину остановки.
5. Перевести интерфейс в состояние ABORTED.

Не блокировать команду OFF длительным чтением порта.

При потере связи немедленно остановить сценарий и показать предупреждение: физическое состояние выходов не подтверждено.

При FAULT:
- Прекратить эксперимент.
- Не выполнять автоматический ARM.
- Не сбрасывать FAULT автоматически.
- Не продолжать последовательность.

При закрытии программы во время эксперимента попытаться отправить OFF и предупредить оператора, если подтверждение отключения не получено.

Не объявлять USB OFF гарантированной аппаратной защитой при зависании микроконтроллера.

## 7. Контроль токов и результатов PHOTO

Для каждой операции фиксировать:

- Цвет.
- SOURCE/SINK.
- Команду PHOTO.
- ID операции.
- ACK.
- DONE.
- CURRENT_AVG_UA.
- CURRENT_MAX_UA.
- SAMPLES.
- ELAPSED_MS.
- REASON.
- FAULT.

Проверять, что:
- Фактическая длительность соответствует запрошенной в пределах дискретности и допусков FW.
- Нет аварийного завершения.
- Измерения присутствуют и достоверны.
- Средний ток находится в физически разумном диапазоне для проверенного канала.

Не ослаблять аппаратные и программные пределы FW.

Наличие небольшого расхождения со старыми измерениями само по себе не должно создавать ложную аварию, но существенные отклонения следует показывать и регистрировать.
