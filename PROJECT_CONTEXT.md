# Контекст для продолжения на другом компьютере

Сохранено 15 ноября 2026 года. Репозиторий:
https://github.com/AlexeyNV/GS75_RGB_Research, основная ветка `main`.

## Назначение и границы

Исследовательский стенд RGB-платы клавиатуры MSI GS75 на STM32F411RET6.
Самостоятельный проект, соседний GS75_Keyboard не изменять. Реализуются
диагностика USB CDC, безопасные одиночные импульсы SOURCE/SINK и измерение
тока. GUI, камера, PWM и массовый электрический перебор пока не нужны.
Исходное подробное задание сохранено в [docs/original_task.md](docs/original_task.md).

## Текущее состояние

* `237e026` — первоначальная прошивка FW 0.1.0, схема, библиотеки ST,
  CMake, Python-консоль, тесты и документы.
* `506074b` — исправление ADC и команда ADCSTATUS, FW **0.1.1**.
* Следующий commit сохраняет этот контекст и инструкции переноса.

По сообщению оператора первый аппаратный запуск FW 0.1.0 успешен для USB
DFU, USB CDC, PING, INFO, STATUS. STATUS показывал DISARMED, SRC_EN=0,
SNK_EN=0. Это пользовательский результат, а не испытание, выполненное агентом.
Измерение тока, коммутация на нагрузке и точность ADC ещё не подтверждены.

Обнаруженный дефект FW 0.1.0:

```text
SELFTEST -> ERR ADC_INVALID
CURRENT -> RAW=2 MV=2 CURRENT_UA=16 AGE_MS=115331 VALID=0
```

CONT=1 создавал около 49 тыс. преобразований/с, а DR читался максимум
1000 раз/с; обработка OVR и повторный запуск отсутствовали. Это согласуется
с зависанием после первого результата; аппаратный снимок OVR того запуска
не получен. Обоснование по ST RM0383 и пределы вывода: [docs/adc.md](docs/adc.md).

В FW 0.1.1 ADC_Init/ADC_Poll находятся в `firmware/Core/Src/adc.c`:
CONT=0, программный запуск одного преобразования примерно раз в 1 мс,
неблокирующий сбор EOC, приоритетная обработка OVR, timeout 2 мс,
продолжение сбора в DISARMED и FAULT. ADCSTATUS показывает флаги,
счётчики и возраст последнего допустимого отсчёта. Ошибка выключает
выходы и защёлкивает FAULT; восстановление ADC не снимает блокировку.
Возраст отсчёта считается от запуска, чтобы не освежать просроченный DR.

**Аппаратная проверка исправления FW 0.1.1 ещё не выполнялась.**
Следующий шаг — записать FW 0.1.1 и выполнить пассивную проверку
ADCSTATUS/CURRENT/SELFTEST в DISARMED по docs/adc.md. Сохранить реальные
ответы и интервалы между ними в отдельном журнале испытаний.

## Не менять для маскировки ошибки

ADC_STALE_MS остаётся **5 мс**. SOURCE/SINK не включаются автоматически.
Только явный ARM разрешает PAIR; FAULT снимается явно через CLEARFAULT
после восстановления корректных данных, затем требуется новый ARM.
Коммутация SOURCE/SINK при исправлении ADC не менялась.
U13 разомкнута, R1=2700 Ом, шунт R2=100 Ом, trip=2000 мкА.
Импульс 10–300 мс, ARM максимум 60 с. Первый опыт — без RGB-платы MSI.
GPIO, защиты и порядок испытаний: [docs/bringup.md](docs/bringup.md).

## Что уже проверено программно

ARM GNU GCC 14.3.1, CubeF4 1.28.3, CMake/Ninja: чистая сборка FW 0.1.1
без предупреждений, ELF/BIN/HEX. FLASH 23 108 байт, RAM с резервом стека
12 480 байт. Официальные зависимости ST включены в Git, загрузка SDK для
этой сборки не требуется. Vendor HAL имеет документированное исключение
для предупреждения unused-parameter; собственный код собирается с -Werror.

Два CTest под MSVC x64 проходят: `firmware_logic`, `adc_acquisition`.
Проверены 40 адресов, 1560 направленных пар, парсер, OFF/тайм-ауты,
10 000 измерений по сетке 1 мс в DISARMED, ошибки EOC/OVR/HAL,
потеря измерений, SELFTEST/ARM, FAULT, аварийное отключение и rollover.
Четыре Python-теста сверяют соединения с исходной схемой EasyEDA.
Модель HAL не является аппаратным испытанием.

## Новый компьютер / VSCode

Установить Git, VSCode, Python 3 и STM32CubeCLT (ARM GNU GCC, CMake,
Ninja; CubeProgrammer нужен для записи). Добавить инструменты в PATH.
Для тех же host-тестов Windows установить Visual Studio Build Tools с
компилятором C/C++ и Windows SDK; MSVC необязателен для сборки самой прошивки.

В терминале, в каталоге для проектов:

```powershell
git clone https://github.com/AlexeyNV/GS75_RGB_Research.git
cd GS75_RGB_Research
git log -3 --oneline
code .
```

Если репозиторий уже клонирован, проверить локальные изменения через
`git status`, затем обновить чистую ветку `git pull --ff-only origin main`.
Для закрытого репозитория нужна авторизация GitHub. GitHub CLI не обязателен.

В терминале VSCode из корня проекта:

```powershell
arm-none-eabi-gcc --version
cmake --version
ninja --version
cmake -S firmware -B build/firmware -G Ninja '-DCMAKE_TOOLCHAIN_FILE=cmake/arm-gcc.cmake'
cmake --build build/firmware
python -m pip install -r tools/requirements.txt
python -m unittest discover -s tests -p 'test_*.py' -v
cmake -S tests -B build/host -G 'Visual Studio 17 2022' -A x64
cmake --build build/host --config Debug
ctest --test-dir build/host -C Debug --output-on-failure
```

Генератор host-тестов здесь соответствует проверенному MSVC 2022.
Для другой установленной версии Visual Studio выбрать доступный генератор
из `cmake --help`. На Linux можно использовать host GCC/Ninja.
Каталог `build/` создавать заново: CMake cache содержит абсолютные пути
и не переносится между компьютерами. Расширения C/C++ и CMake Tools в
VSCode удобны, но приведённые команды не зависят от их настроек.

Для CDC: `python tools/serial_console.py --port COM7`, подставив фактический
порт нового компьютера. Baud 115200 в клиенте — настройка CDC line coding,
не UART-интерфейс стенда. Перенос инструментов не требует включать PAIR.

`.ioc` сохранён и обновлён для CONT=0, но открытие/регенерация в GUI
CubeMX ещё не проверены. Рабочий проверенный проект — CMake. Генерировать
CubeMX только в отдельный каталог и сохранять описанные точки интеграции;
не перезаписывать вручную подготовленные Core/USB без проверки.

## Сохранение последующей работы

```powershell
git status
git add <изменённые-файлы>
git commit -m "Описание изменения"
git push origin main
```

Исходники, схема, `.ioc`, тесты, документация и библиотеки хранятся в Git.
Сборки ELF/BIN/HEX, object-файлы, CMake cache, Python cache и локальные
настройки IDE исключены сознательно; они воспроизводятся на новом компьютере.
Локальный commit нужно отправить через push, чтобы он появился на другом ПК.
Весь интерфейс переписки VSCode Git не переносит: этот файл сохраняет
существенный контекст задачи, результаты, ограничения и следующий шаг.

Для нового сеанса агента можно начать так:

> Прочитай PROJECT_CONTEXT.md, docs/adc.md и docs/verification.md.
> Продолжаем GS75_RGB_Research FW 0.1.1. Исправление ADC пока не проверено
> на аппаратуре. Не включай выходы автоматически и не увеличивай ADC_STALE_MS.
